# 3D: real space, built like a film

RasanAI films can mix 2D and 3D scene by scene, and inside one scene. A 3D scene is a real three.js world rendered by **Rasan3D** (`stage3d/rasan3d.js`, installed into a project as `assets/three/`) on the same paused GSAP timeline as the 2D, so a flat card can lift off the page into depth on the frame the cut lands, a camera can fly from one scene into the next, and a label can stay pinned to a point on a turning product. Every frame is a pure function of time, averaged over sub-frames for true motion blur, depth of field and anti-aliasing, and gated before it ships (`stage3d.mjs check`).

Opus is good at this: it can plan a camera, block a scene in world units, light it, land every move on its cue, and write the shader a shot needs. The default it falls back to without a push is the three.js demo: a lone object spinning in a void under a flat light, the camera orbiting at constant speed. That's the film this file exists to beat. **Show off** (§11): plan the space, the light and the seams like a 3D lead at a top studio would, and make the 3D the moment people rewind.

**Invent the technique the shot needs.** Rasan3D is an engine, not a menu. Under the presets (`k.material`, `k.rig`, `k.panel`, `k.svg`, `k.text`: §3, shortcuts for when one happens to be the shot) there is a render graph you write GLSL passes into, deterministic simulations, real DOM pinned in 3D, every three.js addon, a GLSL library (noise, SDF, raymarching, NPR shading), and raw three.js with nothing in the way (§12 to §17). The **design system** (`DESIGN.md`, `frame.md`, the treatment's style bible) is the only bound on the look; techniques are free. The gate stops only what breaks a render (§2); everything else is taste, which the critics judge and a stated intent overrides. A raymarched lattice, an engraved wire, a stippled creature, a swarm that obeys a rule, a card that hangs in the room: if the shot needs it, build it. §18 is a cookbook of techniques, not looks.

Read this when the score (`motion/score.json`) gives a scene `space: "3d"` or `"hybrid"`, when the look is from the 3D & materials family, or when you're scoring a film (the Motion Director decides where 3D goes).

## 1. Where 3D goes

*For a song, the plate-by-plate rule of thumb (documents, charts and type stay 2D; creatures, falls and rooms go 3D; the 2D-to-3D seam is a plate boundary) is in `references/lyric-video.md` §7.*

Every scene has a **space**: `2d` (DOM and GSAP, the default), `3d` (the Rasan3D world is the shot) or `hybrid` (a 3D layer between 2D ground and 2D type). Pick per scene, by what the scene has to show:

| Use 3D when the scene needs… | Example |
|---|---|
| an object to be **an object**: turned, opened, looked around, lit | the product, a device-less UI slab, the logo as a physical thing |
| **space** the story moves through | the camera travelling from the overview into one feature; a corridor of past versions |
| **layers in depth** | the UI exploded into its real layers (shell, panels, content) to show how it's built |
| a **2D thing becoming real** | the flat card from the last scene lifts off the page and turns (flat-to-depth) |
| **many things with one light** | a field of cards, a city of bars (data as architecture), a point cloud resolving into the product |
| **material** as the message | glass (clarity), chrome (precision), clay (friendly), concrete (solid) |

Keep it 2D when the scene is text to read, a dense UI flow the viewer must follow, a chart whose values matter, or anything where depth would only decorate. **One film, one space grammar:** decide how often depth appears (one 3D hero beat; a 3D spine the whole film travels through; 2D with 3D seams at the hinges) and keep to it. A film that flips space every scene without a reason reads as a tech demo.

Rules of thumb for the Motion Director:
- Films of 4 scenes or more get **at least one 3D or hybrid scene**, and films of **20 s or more** need one (or a 3D shot inside a hybrid scene) unless `depth.none_because` (20+ characters, quoting the script line(s) it would hurt) says why. **A flat look is not a reason: it sets the style of the 3D, not whether to use it** ("Brand-flat 3D" below). 3D is a technique for any show it makes stronger: a line's meaning in space (a black hole for "singularity", tilted panels for "research", a dot sphere for "everything you ask"). It must still serve a line, keep every word readable (3D type stays legible, or the line is set in 2D over it) and, in a product-first film, land on the real product.
- The **signature seam or the reveal** is the strongest place for 3D: it's where the film turns, and space is the biggest change you can make.
- Prefer **2D ↔ 3D continuity** to cutting between unrelated worlds (§6).
- 3D scenes cost render time (§10). Two or three hero 3D shots beat eight average ones.

## 2. How a 3D scene is built

Three layers, back to front, all inside one HyperFrames sub-composition and all clocked by one paused timeline:

```
#r3-<frame>-ground   2D  the ground (a clip) and anything the 3D world flies over
#r3-<frame>-gl       3D  the Rasan3D canvas: transparent where nothing is drawn
#r3-<frame>-ui       2D  type, labels, callouts: crisp DOM, animated with GSAP as usual
```

Start from the template, never from a blank file:

```bash
node $SKILL_DIR/scripts/stage3d.mjs install  --project videos/<name>          # once per project (video.mjs inject does it too)
node $SKILL_DIR/scripts/stage3d.mjs scaffold --project videos/<name> --frame <frame_id> --duration <s> \
     --canvas "<frame.md canvas>" --ink "<ink>" --accent "<accent>" [--force]   # writes compositions/frames/<frame_id>.html
```

The scaffold is a valid HyperFrames frame (one `<template>`, styles and scripts inside it, `#root` with `data-composition-id`, `data-duration`, clips with timing, one paused timeline registered at `window.__timelines["<frame_id>"]`, element ids prefixed `r3-<frame_id>-` so they're unique and start with a letter). It already shows the flat-to-depth seam, a lit panel with a shadow on a catcher, DOM type over the 3D, and a 2D label pinned to a 3D point. Replace its world with the score's shots.

```html
<script src="https://cdn.jsdelivr.net/npm/gsap@3.14.2/dist/gsap.min.js"></script>
<script src="assets/three/rasan3d.js"></script>          <!-- project-root relative, inside the <template> -->
<script>
  const tl = gsap.timeline({ paused: true });           // the clock: 2D tweens go on it as usual
  window.__timelines["04-reveal"] = tl;
  Rasan3D.stage({
    id: "04-reveal", canvas: document.getElementById("r3-04-reveal-gl"), timeline: tl, duration: 5.2,
    camera: { pos: [[0, [0, 0, 12]], [1.4, [3.2, 2.1, 7.4], "power3.inOut"]], target: [[0, [0, 0, 0]]], lens: [[0, 50]], fstop: 2.8 },
    async build(k) { /* make the world once; return the things pose() moves */ },
    pose(t, k) { /* set every animated property from t alone */ },
    onDraw(t, k) { /* optional: pin DOM to 3D from the same pose */ },
  });
</script>
```

What the runtime does for you: it adds one clock tween to `tl` (a plain object target, so the motion contract treats it as exempt) and draws on every seek; it holds HyperFrames' render until the scene is built (`window.__hf.buildReady`); it shares one WebGL renderer across every 3D scene in the film (ten 3D scenes, one GL context) and copies each frame into the scene's own canvas; it accumulates sub-frames across a shutter for motion blur, across the pixel for anti-aliasing and across a lens aperture for depth of field; and it tone-maps lit materials while leaving unlit UI faces colour-exact.

**Rules that keep it renderable** (the gate errors on these, and only these):
- **Seek-safe.** `pose(t, k)` (and every pass uniform, every simulation) is a pure function of `t`. No `+=`, counters, physics state or anything carried between calls: the renderer seeks out of order and renders sub-frames around each frame. State that genuinely evolves (a swarm, a fluid, a cloth) goes through `k.simulate` / `k.gpuSimulate` (§13), which are seek-safe by construction.
- **No wall clock, no free randomness, no loop of its own.** Randomness only from `k.rng(seed)`. Never `Math.random()`, `Date.now()`, `performance.now()`, `new Date()`, `requestAnimationFrame`, `setAnimationLoop`. In shaders, hash from position or a seed uniform; never from the clock.
- **One renderer.** Never your own `WebGLRenderer` (a GL context per scene runs out at ~16 and skips the blur, DoF and grade). Extra render targets, scenes and cameras are fine (`k.target`, `k.view`).
- **Offline.** Assets from the project (`assets/...`, project-root relative), loaded in `build()`. Never a URL at render time, never three.js from a CDN.
- **No controls.** No OrbitControls and friends: the camera is keys or a function of `t`.
- **Not blank, and renderable.** A frame that is a flat field is an error (unless `declare: { plain: true }`); a final frame over 20 s (`frame-cost`) is an error: it cannot be rendered in reasonable time (over 2.5 s is a warning with the estimated render minutes).
- The scene built, and the runtime is installed (`build-failed`, `runtime-path`, `runtime-missing`).

**Everything else is taste, and a warning.** `linear-drift` (a constant-speed key), `never-rests`, `stock-primitive`, `placeholder-material`, `fast-without-blur`, `implicit-ease`, `custom-ease`, and `ease-outside-set` for 3D keys (the 2D tweens in `obey.mjs` stay strict) tell you what a critic will say. If you did it on purpose, **declare the intent** and the warning is silenced for that rule:

```js
Rasan3D.stage({ ...,
  declare: { intent: {
    "linear-drift": "the endless glide across the floor is the shot",   // rule id -> why (12+ characters)
    "never-rests":  "the film is one unbroken flight; resting would end it",
  } },
});
```

A reason under 12 characters doesn't count. The report lists every declared intent (`declared-intent`, with the reason) so the critics see it and judge whether it holds on screen. An intent is a claim about the shot, never a way around a note you don't want to fix. `declare: { linear: ["<track>"] }` (the old form) still works for one track; `declare: { plain: true }` allows a deliberately flat frame. Eases are GSAP names from `motion.md`, written on the keys (a key with no ease falls back to `power2.inOut` and warns).

## 3. API

### `Rasan3D.stage(options)`

| Option | Default | What |
|---|---|---|
| `id` | required | the composition id (the `window.__timelines` key) |
| `canvas` | required | the scene's canvas element (or a selector) |
| `timeline` | required | the scene's paused GSAP timeline: the clock |
| `duration` | `timeline.duration()` | seconds; set it (the timeline may be shorter than the scene) |
| `width`, `height`, `fps` | 1920, 1080, 30 | the composition's size and frame rate (fps sets the shutter) |
| `camera` | — | declarative camera keys (below). Use it: the gate checks its eases, and `layout()` reads it |
| `motionBlur` | `{ shutter: 0.5 }` | shutter as a fraction of the frame (0.5 = 180°); `samples: N` fixes the count; `false` turns it off (set it for the delivery render, where `finish.mjs` blurs every scene; see §4) |
| `antialias` | `true` | at least 4 jittered samples per frame in final quality |
| `environment` | `"studio"` | image-based light for reflections: `"studio"`, `"soft"`, `"none"`, or `{ preset, intensity }` (default intensity 0.5) |
| `background` | transparent | a colour makes the 3D layer opaque (needed under glass, §5) |
| `fog` | — | `{ color, near, far }`: atmospheric depth; colour it like the ground |
| `toneMapping`, `exposure` | `"neutral"`, 1 | lit materials only: `neutral` keeps brand colours, `agx` is filmic, `aces` punchy, `none` |
| `post` | `{}` | `bloom: { strength, threshold (1.15), knee, radius }`, `halation`, `grain` (0.015–0.04), `vignette`, `ca` (px), `saturation`, `lift: [r,g,b]`, `gain: [r,g,b]`. Post touches only what the 3D layer draws |
| `near`, `far`, `unitsPerMeter` | 0.05, 400, 1 | clip planes; world units per metre (for the f-stop) |
| `pixelRatio` | the device's (≤ 2) | render scale; only for small previews (the console's style tiles), never in a film |
| `build(k)` | — | async; make the world once; return an object (it becomes `k.objects`) |
| `pose(t, k)` | — | place everything at local time `t` |
| `onDraw(t, k)` | — | after each frame: DOM pinned to 3D (`k.toScreen`) |
| `graph(k)` | — | the render graph (§12): register GLSL passes, targets and views, after `build` |
| `declare` | — | `{ intent: { "<rule>": "<reason, 12+ chars>" }, plain: true, linear: [track names] }`: what you did on purpose (§2). `plain` = a deliberately flat frame |

### Camera keys

```js
camera: {
  pos:    [[t, [x, y, z]], [t, [x, y, z], "power3.inOut"], …],   // or a function of t: Rasan3D.orbit({...})
  target: [[t, [x, y, z]], …],     // where it looks
  lens:   [[t, 50], …],            // focal length in mm, full frame (36 mm on the frame's long side)
  roll:   [[t, 0], …],             // degrees
  focus:  [[t, "target"]],         // focus distance: "target" (default) or a number
  fstop:  2.8,                     // real depth of field (or aperture: <radius in world units>); both keyable: [[t, 1.8], [t2, 4, "power2.inOut"]]
  shift:  [[t, [0, 0.12]]],         // lens shift in fractions of the frame (+y raises the frame): verticals stay vertical, keyable
}
```

Keys are `[time, value, ease]`; the ease is the ease **arriving at** that key (like a GSAP `.to`); before the first key the value holds, after the last it holds. A key that repeats the previous value is a hold.

| `k.addon(path)` | any addon of the vendored three.js r181 `examples/jsm` tree, by its path under `addons/` (§14): `await k.addon("loaders/GLTFLoader.js")`, `"misc/GPUComputationRenderer.js"`, `"objects/MarchingCubes.js"`, `"lines/Line2.js"`, … |
| `k.pass(name, opts)`, `k.target(name, opts)`, `k.targetTexture(name)`, `k.view(name, opts)` | the render graph: your own GLSL passes, named render targets, other scenes rendered into targets (§12; call them in `graph(k)`) |
| `k.simulate(name, opts)`, `k.gpuSimulate(name, opts)` | deterministic simulation: `.at(t)` is the state at time `t` under any seek order (§13) |
| `k.pinDom(el, opts)` | a DOM element placed exactly on a rectangle in the 3D view (§13b) |
| `k.glsl`, `k.include(src)`, `k.hash(i, seed)` | the GLSL library chunks (§15); expand `#include <r3/name>` in a shader string; a seeded 0..1 hash of an integer |
| `k.tube(pointsOrFn, opts)`, `k.instanceField(opts)` | a tube geometry with engraving-friendly UVs; an endless instanced field tiled around the camera (§15) |

A GLB model from the project: `const { GLTFLoader } = await k.addon("loaders/GLTFLoader.js"); const g = await new GLTFLoader().loadAsync("assets/models/x.glb");` (animated clips: an `AnimationMixer`, `mixer.setTime(t)` in `pose`).

## 4. Camera: plan it like a DP

**World units are metres.** Block the scene at real scale (a phone is 0.15, a laptop 0.3, a room 4) and the lens and f-stop behave like a real camera's. Put the subject near the origin, the floor at y = 0 or below it.

| Lens | Feel | Use |
|---|---|---|
| 14–24 mm | exaggerated space, strong perspective, near things huge | flying through a world, architecture, the inside of something |
| 35 mm | natural, documentary | moving through a space with the viewer |
| 50 mm | neutral, honest | the default; UI slabs, objects at arm's length |
| 85–135 mm | compressed, flattered, background melts | product hero, the reveal, type in space |
| 200 mm+ | flat, graphic, stacked layers | a row of objects compressed into a pattern; a calm, monumental hold |

| Move | Build it | Feel |
|---|---|---|
| push-in (dolly) | `pos` toward `target`, lens fixed | intimacy, attention; near things grow faster than far (parallax) |
| zoom | `lens` changes, `pos` fixed | flat, graphic, a "look closer" |
| dolly zoom | `pos` back while `lens` lengthens (or the reverse), subject size held | vertigo, realisation; once per film at most |
| truck / track | `pos` and `target` slide sideways together | following, revealing a row |
| crane / pedestal | `pos.y` rises or falls with `target` | reveal of scale, an arrival |
| orbit / arc | `pos: k.orbit({…})`, 15–60° over the shot, eased | understanding an object; never a full constant-speed spin |
| rack focus | `focus` keys from one distance to another, fstop 1.8–2.8 | shifting attention between two planes |
| whip | a fast `target` swing (0.15–0.3 s, `expo.inOut`) with motion blur | a hard change of subject; cut at the blur's peak |
| fly-through | `pos` through an opening along a path, wide lens | going inside: the transition into the next scene |

- **One move per shot**, motivated (toward what matters, away to reveal context, with an action). Hold before and after: land, then let it be read. A camera that never stops is the screensaver (the gate warns `never-rests`).
- **Ease every leg**: `power3.inOut` or the film's `move` ease for repositioning, `expo.out` or `power4.out` for a slam that lands, `sine.inOut` for slow, luxurious drift. Constant speed (`none`) is the screensaver look and the gate warns `linear-drift`; if the endless glide *is* the shot, declare the intent (§2) and make something happen on screen.
- **Lead the subject**: the camera arrives 0.1–0.2 s after the subject's own move starts, never at the same instant.
- **Camera tiers still apply** (`craft.md` §6): T0 locked, T1 push (a move that goes somewhere, 4% a second or faster; a slow drift is a creep), T2 focus move into a region, T3 the one crash move.
- **With the delivery finish, the stage does not blur** (`references/finish.md`, `scripts/finish.mjs all`): the finish gives every scene, 2D included, one 180° shutter, so set `motionBlur: false` in each `Rasan3D.stage({...})` before the delivery render (the gate's `fast-without-blur` warning is then expected). The one exception is a whip-speed 3D move (over about 3 000 px/s on screen): keep `motionBlur: { shutter: 0.25 }` on that scene and pass `--shutter 0.25` to the finish. Drafts skip the finish and keep the default.
- Motion blur is on by default (180° shutter). Fast camera moves read as speed, not strobing; a still frame costs 4 samples.
- Depth of field: f/2–2.8 for a product hero or a rack focus, f/4–5.6 for a readable UI slab, off for text-heavy frames.

## 5. Light and materials

**One motivated key**, a direction and a colour, and everything agrees with it: the rig's `dir`, the shadow, the rim, any 2D shadows on the same scene. Choose the rig by mood:

| Rig | Look | For |
|---|---|---|
| `three-point` | key, soft fill, back rim | the neutral default; products, UI slabs |
| `top-soft` | a big soft top light, gentle wrap | products on a sweep; clean, Apple-like |
| `rim` | dark, sculpted by back light | dramatic reveals, chrome, type in the dark |
| `low-key` | one hard key, deep shadow | tension, the problem beat, cinematic |
| `window` | broad side light | warm, human, editorial |

Materials by the look's 3D family (the style's palette gives the colours; the accent is the one emissive or saturated thing):

| Style | Material | Light | Notes |
|---|---|---|---|
| Glass 3D | `glass` / `frosted-glass` | `rim` or `three-point`, `environment: "studio"` | glass refracts only what the 3D layer draws: give it an opaque `background` or a backdrop plane, never bare DOM behind it |
| Chrome / liquid metal | `chrome` | `rim`, environment 0.8–1.2 | metal is its reflections: it needs the environment and something to reflect |
| Matte ceramic, soft 3D | `ceramic` / `clay` | `top-soft`, soft shadows (`shadowSoftness` 8–12) | low saturation, big radii, slow moves |
| Gummy / gel | `gummy` | `three-point` with a warm rim | `background` set; light passes through |
| Concrete brutalist | `concrete` | `low-key` or `window`, hard shadows | monumental lens (85 mm+), slow crane |
| Point cloud | points from `k.surfacePoints` (a `Points` with an `unlit`/emissive look) | none needed | resolve the cloud into the product on the beat |
| Paper / editorial | `paper`, planes with print textures | `window` | real folds and curls; type stays DOM |
| Product UI | `panel` with the real screenshot (`k.image`) | `three-point` | the face is unlit: the UI keeps its exact colours |

Bloom touches only HDR light (`emissive` at intensity 2–4). UI white and lit surfaces stay below the threshold on purpose: glow on everything is slop.

## Brand-flat 3D

A flat brand (a card that says no blur, no grain, no glow) restricts the **style** of 3D, never its use. OpenAI's own "Refreshed." is a rotating sphere of dots: that is flat 3D. The recipe:

| | Brand-flat style |
|---|---|
| Materials | `k.material("unlit", { color })`, `"matte"`, MeshBasic, MeshToonMaterial or flat-shaded (`flatShading: true`) in the brand's palette, exact hex. Score `materials` names one of: basic, toon, flat, matte, unlit, lambert |
| Light | clean and even: `k.rig("top-soft", { shadows: false })` or none for unlit faces; `environment: "none"` or a low `{ preset: "soft", intensity: 0.2 }`; any shadow soft and in the palette's grey |
| Off | `post: {}` (no bloom, glow, grain, halation, chromatic aberration, lens flare), no `emissive`, no `chrome`, `glass`, `gummy` |
| Blur | `fstop` (depth of field) only when the card allows blur, else leave it out; `motionBlur` on fast moves only when the card allows blur, else `motionBlur: false` and keep moves slow enough to read without it |
| Camera | the card's moves still bind: ease every leg, `power3.inOut`, a hold at the end; a longer lens (85 mm+) keeps flat shapes graphic |
| Type | readable type stays DOM above the 3D (§7); the 3D never carries a line the viewer must read unless it is large and faces the camera |

**The dot sphere** ("Refreshed."): the dot field of the 2D grid becomes a rotating sphere of identical flat dots, then collapses to one dot.

```js
// build: N dots on a Fibonacci sphere, one InstancedMesh of flat discs facing the camera
const T = k.THREE, N = 900, R = 2.2;
const dots = new T.InstancedMesh(new T.CircleGeometry(0.045, 20), k.material("unlit", { color: "{{INK}}" }), N);
const dir = []; for (let i = 0; i < N; i++) { const y = 1 - 2 * (i + 0.5) / N, r = Math.sqrt(1 - y * y), a = i * 2.399963; dir.push([r * Math.cos(a), y, r * Math.sin(a)]); }
k.scene.add(dots); const m = new T.Matrix4(), s = new T.Vector3(), p = new T.Vector3();
// pose(t): from the 2D grid plane (flat) to the sphere, then the sphere to one dot, all from t alone
const form = k.prog(t, 0.2, 1.6, "power3.inOut"), turn = k.at(t, [[1.0, 0], [4.0, 1.4, "power2.inOut"]]), collapse = k.prog(t, 4.4, 5.2, "expo.in");
const c = Math.cos(turn), sn = Math.sin(turn), g = new T.Vector3();
for (let i = 0; i < N; i++) {
  const [x, y, z] = dir[i];
  g.set(((i % 30) - 14.5) * 0.18, (Math.floor(i / 30) - 14.5) * 0.18, 0);                 // its place on the flat grid
  p.set((x * c + z * sn) * R, y * R, (-x * sn + z * c) * R).lerp(g, 1 - form);            // grid -> turning sphere
  p.multiplyScalar(1 - collapse);                                                          // sphere -> one dot at the origin
  s.setScalar(i === 0 ? 1 + 14 * collapse : 1 - collapse);                                 // dot 0 survives and grows
  m.compose(p, k.camera.quaternion, s); dots.setMatrixAt(i, m);                            // discs face the lens
}
dots.instanceMatrix.needsUpdate = true;
// stage: camera lens [[0, 85]] (flat, graphic), no fstop, motionBlur: false, post: {}, environment: "none"
```

**The tilted panels** (a "research" line; the real UI on slabs in depth): three real screenshots on `panel`s, stepped in z and tilted 18 to 25 degrees, an even light, the face unlit so the UI keeps its exact colours; no glow, edges drawn as a 1 px palette line instead.

```js
const ppu = k.layout({ at: 0, distance: 12 }).userData.pxPerUnit;
const shots = ["assets/ui-1.png", "assets/ui-2.png", "assets/ui-3.png"].map((u) => k.panel({ width: 1100 / ppu, height: 660 / ppu, depth: 0.06, radius: 0.12, texture: k.image(u) }));
shots.forEach((p) => k.scene.add(p)); k.rig("top-soft", { shadows: false });
// pose(t): they fan out on the beat, each landing 0.12 s after the last, then hold
shots.forEach((p, i) => { const a = k.prog(t, 0.4 + i * 0.12, 1.2 + i * 0.12, "expo.out");
  p.position.set(k.THREE.MathUtils.lerp(0, (i - 1) * 2.6, a), 0, -i * 0.6 * a);
  p.rotation.y = -0.38 * a * (i - 1 || 0.5); });
// stage: camera lens [[0, 50]], motionBlur: false unless the card allows blur, post: {}
```

The other flat-3D shots are the same recipe: cells that flip as cards about a rule (`panel`s on one hinge axis), a grid that tilts into a receding plane (a `pxPlane` in the room, camera `shift` and a 135 mm lens), a letter extruded in matte (`k.extrudeText` with `k.material("matte")`), a specimen turning on its label axis. Check each in `stage3d.mjs stills` against the brand card's frames: if the 3D could be mistaken for another brand's film, move it toward the card's palette and flatness.

## 6. 2D ↔ 3D seams (where the planning shows)

The cut between a 2D scene and a 3D one is where this pays off or falls apart. Plan these seams in the score (`kind` below, with handoff numbers in px like any continuity seam) and build them exactly:

| Seam | What happens | Build |
|---|---|---|
| `flat-to-depth` | the last frame of a 2D scene **is** the first frame of the 3D one; then the flat thing lifts into space | in `build`: `const g = k.layout({ at: 0, distance: D })`; put the object (a `panel`, a `pxPlane` with the same screenshot) at the 2D element's exact px rect in `g` (`g.userData.pxPerUnit` converts px to world). The camera's t = 0 key is the layout pose; move it after a short hold (0.1–0.3 s) |
| `depth-to-flat` | the 3D move lands on a pose where an object fills an exact px rect; the next 2D scene starts there | lay the object out with `k.layout({ at: <end time> })`; the camera's last key is that pose; hold 2+ frames before the cut |
| `camera-through` | one continuous camera move crosses the cut: the camera flies into something in scene N (a screen, a window, the O of a word) and scene N+1 opens inside it | velocity-match: scene N's last camera leg and N+1's first leg share direction and speed (write both in the seam's `out` / `in`: `speed` in px/s of the subject or world units/s, `direction`); cut at peak speed under motion blur |
| `shared-element` (2D ↔ 3D) | a DOM element and a 3D object are the same thing across the cut (a button becomes a slab, a logo extrudes) | the 3D object is laid out at the DOM element's px rect at the seam time (`layout`); its colours match exactly (unlit face, same texture) |
| `pinned` (inside a hybrid scene) | 2D labels, cursors and leader lines ride on 3D points | `onDraw`: `const p = k.toScreen(point)`, set the DOM element's transform; hide it when `!p.visible` |

Seam discipline: the frames on both sides match to within a pixel and a colour level (look at a strip across the cut at 15 fps). An exact match is what makes the viewer believe the flat thing and the 3D thing are one object, and it's what they rewind to see.

## 7. Type and UI in 3D

- **Readable type stays DOM** in the `ui` layer above the 3D, set from `frame.md`: crisp at every size, animated with the film's text techniques, checked by the motion contract.
- **Display type can be 3D** when its being an object is the point: `k.extrudeText` in the brand's TTF/OTF (a hero word, a number, the end card), or `k.text` on a plane for type that sits in the world (a sign, a label on a surface). Nothing under ~48 px on screen in 3D.
- **The product's UI in 3D** is the real screenshot on a `panel` (never a mock): one slab for the screen, or exploded layers (shell, sidebar, content, the focused component) at z offsets 0.05–0.3 that separate on the beat and close back. The cursor stays DOM, pinned to the 3D point it clicks (`toScreen`).
- **The logo** is the official SVG through `k.svg` / `k.svgUrl`: never redrawn, never stretched; extrude depth 2–6% of its width.

## 8. Motion in 3D

The animation principles hold in depth: one primary mover per beat; secondaries 80–200 ms behind; arcs; overlap and follow-through (a slab lands, its layers settle 2–4 frames later); anticipation in the style's register. 3D adds:
- **Rotations land**: turn an object to a composed angle and hold it; 15–40° reads as "look at this", 180° as "the other side". No idle spin.
- **Scale the move to the lens**: the same 1 m of travel is violent on 24 mm and calm on 135 mm.
- **Parallax is the proof of depth**: put something near the lens (a blurred foreground slab, a row of cards) when the camera moves, or the 3D reads flat.
- **Assembly**: pieces fly in from seeded positions to their layout, staggered outward from the origin, each on `expo.out`; the last lands in the back half of the shot.

## 10. Cost

On a Mac with a GPU (HyperFrames renders with the hardware GPU when it can), a hybrid scene renders in about real time to a few times real time. Under software GL (no GPU) a final frame with 16–24 samples, shadows and glass can take seconds. Keep it in budget:
- transmission (glass, gummy) on the hero only; everything else opaque
- one shadow-casting light (the key); fill and rim without shadows
- merge static geometry; reuse materials; textures at the size they appear
- `motionBlur.samples` lower (8) on long moves that are mostly calm; let `auto` decide otherwise
- check `frame-cost` in the gate (a warning over 2.5 s, an error over 20 s), and look at the final-frame time in its report
- custom passes: a raymarch pass costs `samples × steps × pixels`; cap `R3_STEPS`, raise `R3_CONE` so far hits stop early, and move anything that doesn't need blur into an `at: "post"` pass
- simulations: `k.simulate` pays `t / dt` steps for a first late access; a coarser `dt` or fewer particles keeps it cheap

## 12. The render graph: your own passes, targets and views

`graph(k)` runs once after `build` (so `k.objects` and the scene exist) and registers steps in order. It is how you write a shader into the film: a raymarched world, a screen-space look, a second camera.

```js
Rasan3D.stage({ ..., async build(k) { … }, pose(t, k) { … },
  graph(k) {
    k.pass("name", { frag, uniforms, at: "scene" | "post", depth, blend, target });
  } });
```

**`k.pass(name, { frag, uniforms, at, depth, blend, target })`**: a full-screen GLSL ES 3.00 fragment pass.

- `at: "scene"` (default) runs **inside the sample loop**, once per sub-frame, so it gets exactly the motion blur, depth-of-field jitter and anti-aliasing the meshes get. It draws over what the sample's meshes drew. `at: "post"` runs once on the accumulated frame, before the stage's final grade (bloom, grain, vignette); post passes chain in registration order.
- Your fragment writes `gl_FragColor` (premultiplied alpha) and `gl_FragDepth` if it composites by depth; `void main()` is yours and the prelude (below) is prepended. It is compiled as a three.js `ShaderMaterial` on WebGL2 (GLSL ES 3.00 features such as `for` with `int`, arrays and `fwidth` work).
- `blend`: `"over"` (default for scene passes: alpha-over what is there), `"add"`, `"replace"` (default for post), or `"min-depth"` (composite by depth against the rasterised meshes, below).
- **`depth: true`** (or `blend: "min-depth"`) with a fragment that writes `gl_FragDepth` makes the pass depth-test against the meshes, so a raymarched world and ordinary geometry intersect correctly. Write `gl_FragDepth = r3Depth(worldPoint);`. Without a `gl_FragDepth` write the pass can't depth-test and just draws over.
- `uniforms`: `{ uName: value }`. A value is a number, an array of 2 to 4 numbers (a vector), a `"#rrggbb"` colour, a texture or three.js object, or **a function `(t, k) => value` evaluated per sample** with `t` the sub-frame time (that is what makes it blur). Declare each in your GLSL (`uniform float uName;`). Time-varying values must be pure functions of `t`.
- `target`: render the pass into a named target (below) instead of the frame; later passes read it as `uTarget_<name>` (declared for you), materials as `k.targetTexture(name)`.

**The prelude** (every pass): `r3Tone(vec3)` (the stage's tone map: apply it to lit, HDR colours your pass produces so they match the meshes; leave flat design colours alone), `saturate`, uniforms `uTime` (the sub-frame time), `uFrame`, `uRes`, `uCamPos`, `uCamMatrixWorld`, `uView`, `uViewInv`, `uProj`, `uProjInv`, `uViewProj`, `uNear`, `uFar`, and `varying vec2 vUv`. Helpers: `rayDir(vUv)` (the world ray of this pixel), `r3Depth(worldPoint)` (the 0..1 depth value to write to `gl_FragDepth`), `r3Z(worldPoint)` (view distance along the camera axis), `r3Fwd()`. Scene passes also get `uSceneColor` / `uSceneDepth` (what the meshes drew this sample; depth is linear view distance, `1e6` where nothing) with `r3Scene(uv)`, `r3SceneZ(uv)`, `r3SceneT(uv, rd)`; post passes get `uSrc` (the accumulated frame, `r3Src(uv)`) and `uDepth` (the last sample's depth). `#include <r3/noise>` (and the other chunks, §15) are expanded for you.

**`k.target(name, { w, h, scale, type: "half" | "float" | "byte", depth, samples, filter })`** makes a render target (default: the frame's size, half float). `k.targetTexture(name)` is its texture for a material or a pass. **`k.view(name, { scene, camera, target, hide, pose(t, k), environment })`** renders another scene with another camera into a target every sample (a portal, a screen showing a world, a reflection, a picture in picture); `pose(t, k)` poses that world from the sub-frame time. Targets are cleared per sample; a view's target has depth and 4× MSAA unless you made it yourself.

Cost: a scene pass runs per sample (4 to 24 times a frame); keep raymarch steps and resolution in check, and put work that doesn't need blur in a `post` pass. The gate measures the busiest frame (§2: an error over 20 s).

## 13. Simulation, DOM in 3D

**Deterministic simulation.** A physical thing that carries state (a swarm, cloth, a fluid, a growing structure) must still be a pure function of `t` when the renderer seeks. `k.simulate` does it:

```js
const sim = k.simulate("swarm", {
  dt: 1 / 120, checkpointEvery: 0.5,
  init(state, k)      { /* fill state with typed arrays and numbers, seeded from k.rng(seed) */ },
  step(state, dt, t, k) { /* advance one fixed step; t = the step's time */ },
});
// in pose(t, k):
const s = sim.at(t);           // the state at time t, whatever order frames are asked in (treat it as read-only)
```

State is fixed-step integration from `init`; a checkpoint (a structured clone) is stored every `checkpointEvery` seconds as the integration passes, so a seek restarts from the nearest checkpoint at or before `t`, not from 0. The first access to a late `t` fast-forwards from 0 (budget for `t × 1/dt` steps; a few hundred thousand cheap steps is fine, a million heavy ones isn't). The fraction of a step between steps is integrated on a throwaway copy, so any `t` gives a smooth state. Seeded randomness only; no clock, no `Math.random`. The attractors and forces inside `step` are functions of `t` (the argument), never of the wall clock. The gate's seek-safety check passes simulated scenes because they are.

**`k.gpuSimulate(name, { size, fields, init, step, dt, checkpointEvery, uniforms, seed })`** is the same contract on the GPU (three's `GPUComputationRenderer`): state lives in float textures (`size` is a number or `[w, h]`; `fields` names the textures, default `["state"]`, sampled as `tState`; `"pos"` is `tPos`). `init` and `step` are GLSL fragment bodies in `GPUComputationRenderer` style (`vec2 uv = gl_FragCoord.xy / resolution.xy; gl_FragColor = …`) with `uDt`, `uTime` (= step × dt), `uStep`, `uSeed`, `r3Hash(vec2)` and every field's sampler available; give them as objects keyed by field for several fields. `sim.at(t)` returns `{ texture, textures, size, step, time }`; read it in `pose` and bind the texture to a material (`points` or instanced mesh that samples it in its vertex shader). State is quantised to `dt` (use a small `dt`, 1/240). Seeking backwards restores a stored texture copy at the nearest checkpoint; seeking forwards steps. Cost is `t / dt` GPU steps for a first late access, so keep the scene short or `dt` coarse when the simulation is heavy. Call `sim.at(t)` from `pose` (not `build`: the compute module loads first).

```js
const sim = k.gpuSimulate("flow", { size: 64, dt: 1 / 120, seed: 5,
  init: `void main() { vec2 uv = gl_FragCoord.xy / resolution.xy; gl_FragColor = vec4((r3Hash(uv) - 0.5) * 4.0, (r3Hash(uv + 7.0) - 0.5) * 4.0, 0.0, 1.0); }`,
  step: `#include <r3/noise>
    void main() { vec2 uv = gl_FragCoord.xy / resolution.xy; vec4 s = texture2D(tState, uv);
      gl_FragColor = vec4(s.xy + r3Curl2(s.xy * 0.5, uTime * 0.3) * 1.5 * uDt, 0.0, 1.0); }` });
// a Points mesh whose vertex shader reads texture2D(tPos, aRef); in pose: material.uniforms.tPos.value = sim.at(t).texture;
```

**13b. DOM in 3D: `k.pinDom(el, { at, width, height, face, px, offset, backface })`.** Puts a real DOM element (crisp type, GSAP-typed text, a whole card) exactly on a rectangle in the 3D view: every draw sets its CSS `transform: matrix3d(...)` to the true perspective map of that rectangle, from the final pose (so it agrees with motion blur and depth of field's centre frame). `at` is an `Object3D` or `[x, y, z]` (the rectangle's centre), `width` / `height` in world units (height defaults to the element's aspect), `face: "camera"` (default: it faces the lens) or `"object"` (it lies on the object's plane and turns with it; for a bare point add `rotation: [x, y, z]`), `px: [w, h]` the element's own CSS box (the element keeps its pixel size, so type stays crisp), `offset: [x, y, z]` in the rectangle's own axes (the card's own plane is `z = 0`; offset it 0.06 along `z` to sit just proud of a slab's face), `backface: "hide"` to hide it when seen from behind. Put the element in the scene's `ui` layer; the runtime takes over its `position` and `transform`. DOM is never occluded by meshes (it is hidden only when a corner is behind the camera): lay out so nothing passes in front of it, or fade it by hand.

`k.addon("<path>")` imports any module of three.js r181's `examples/jsm` tree from `stage3d/addons/` (relative imports rewritten, offline, no CDN), as a promise of the module: `const { Line2 } = await k.addon("lines/Line2.js")`. The categories, all there:

## 15. The GLSL library and geometry helpers

JS helpers (also `Rasan3D.tube`, `Rasan3D.instanceField`):

- **`k.tube(points | fn(t) -> [x,y,z], { radius (number | fn(u)), segments (160), radial (16), closed, tension })`** -> a `BufferGeometry`: a smooth tube with **`uv.x` = arc length 0..1 along it and `uv.y` = 0..1 around it** (seamless), plus `aLen` (world arc length) and `aTangent`; `geometry.userData.length` is the total length. Lines running along the wire are lines of constant `uv.y` (`r3Engrave(uv.y, tone, 12.0)`); rings around it are `uv.x * length / spacing`. A wire, a cable, a ribbon of engraved light.

## 16. Raw three.js

Everything above is optional. `k.THREE` is the full vendored three.js r181: `k.scene`, `k.camera`, your own meshes, `ShaderMaterial` and `onBeforeCompile` patches, `InstancedMesh`, `Points`, `BufferGeometry` built from your own math, `Object3D` hierarchies, `AnimationMixer` (`mixer.setTime(t)`), render targets, an addon's whole API. Add it in `build`, pose it from `t` in `pose`. The runtime renders the scene (shared renderer, tone map, sample accumulation, post); what stays out of reach is only what would make frames depend on state or the network (§2). A `ShaderMaterial` in a mesh and a render-graph pass both write `gl_FragColor`. Lit three.js materials are tone-mapped by the stage; if your shader outputs final display colour, set `toneMapped: false` on it.

## 17. The design system is the only bound on the look

The film's look comes from its design system: `DESIGN.md`, `frame.md` (canvas, ink, accent, type) and the treatment's style bible. A palette, a type voice, a material family, a mood: those are binding, in 3D as in 2D. **Nothing else is**: no list of approved shapes, shaders or effects. If the style is "engraved", you may write the engraving; if it is "clay", the clay is the material preset or your own; if the story needs a world the presets can't make, write the world. The presets (`k.material`, `k.rig`, `k.panel`, `k.svg`, `k.text`, `k.extrudeText`, `k.ground`) are shortcuts for when one happens to be the shot. A scene that reaches for a preset where the shot called for an invented technique is what the critics call out; a technique that fights the style bible is what they reject.

## 18. Cookbook: techniques, not looks

Each sketch is a technique, short and tested in this runtime; none is a look. The look comes from your design system (colours, line weights, type, mood) and the shot. **Invent the technique the shot needs**: combine these, bend them, or write something none of them is.

**A raymarched SDF world, composited by depth with ordinary meshes.** The pass raymarches in `scene` space and writes `gl_FragDepth`, so the ball below passes through the lattice correctly and both get the motion blur and DoF.

```js
graph(k) {
  k.pass("lattice", {
    at: "scene", depth: true, blend: "min-depth",
    uniforms: { uTwist: (t) => 0.12 * Math.sin(t) },
    frag: `
      #include <r3/sdf>
      #include <r3/npr>
      uniform float uTwist;
      float map(vec3 p) {
        p = r3Twist(p, uTwist);
        vec3 q = r3Rep(p, vec3(1.2));
        float cell = r3Subtract(r3SdRoundBox(q, vec3(0.32), 0.05), r3SdSphere(q, 0.4));
        return r3Intersect(cell, r3SdSphere(p, 3.2));
      }
      #include <r3/raymarch>
      void main() {
        vec3 rd = rayDir(vUv);
        R3March m = r3March(uCamPos, rd, uNear, uFar);
        if (!m.hit) discard;
        vec3 p = uCamPos + rd * m.t, n = r3Normal(p, 0.002), l = normalize(vec3(-0.5, 0.8, 0.6));
        float tone = r3Wrap(n, l, 0.2) * r3SoftShadow(p + n * 0.02, l, 0.02, 6.0, 10.0) * mix(0.4, 1.0, r3AO(p, n, 0.5));
        gl_FragColor = vec4(mix(vec3(0.04, 0.05, 0.08), vec3(0.93, 0.9, 0.82), tone), 1.0);   // your palette here
        gl_FragDepth = r3Depth(p);
      }`,
  });
}
```

Swap the shading for `r3Hatch` / `r3Stipple3FW` (with `r3FootprintU` for the pixel footprint) to get a hatched or stippled raymarched object; for a scene with no meshes at all, drop `depth` and `blend`.

**Engraved lines along a wire.** `k.tube` gives UVs with `uv.y` around the tube, so constant-`uv.y` lines run along it; `r3Engrave` swells them with shadow and keeps widths pixel-stable.

```js
const geo = k.tube((u) => [1.3 * Math.sin(u * 12.566), (u - 0.5) * 3.2, 0.8 * Math.cos(u * 18.85)], { radius: 0.12, segments: 600, radial: 24 });
const mat = new k.THREE.ShaderMaterial({
  uniforms: { uLight: { value: new k.THREE.Vector3(-0.5, 0.8, 0.6).normalize() } },
  vertexShader: `varying vec2 vUv; varying vec3 vN;
    void main() { vUv = uv; vN = normalize(mat3(modelMatrix) * normal); gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
  fragmentShader: k.include(`
    #include <r3/npr>
    uniform vec3 uLight; varying vec2 vUv; varying vec3 vN;
    void main() {
      float tone = r3Wrap(normalize(vN), uLight, 0.25);
      float ink = r3Engrave(vUv.y, tone, 12.0);                    // 12 lines along the wire
      gl_FragColor = vec4(mix(vec3(0.94, 0.91, 0.86), vec3(0.08, 0.07, 0.07), ink), 1.0);
    }`),
});
k.scene.add(new k.THREE.Mesh(geo, mat));
```

**An endless field of anything.** The camera flies; the field re-tiles around it, deterministic per cell.

```js
const field = k.instanceField({

  cell: 1.2, count: [44, 44], seed: 7,
  place(cx, cz, rng, o) { const h = 0.2 + rng() * rng() * 4; o.scale = [1, h, 1]; o.y = h / 2; o.yaw = 0; o.visible = rng() > 0.15; },

k.scene.add(field);          // camera keys carry the camera down -z; add fog to hide the far edge
```

**A deterministic particle simulation.** State evolves in `step`; `pose` only reads `sim.at(t)`.

```js
const sim = k.simulate("swarm", {
  dt: 1 / 120, checkpointEvery: 0.5,
  init(s, k) { const r = k.rng(3); s.p = new Float32Array(N * 3); s.v = new Float32Array(N * 3); s.o = new Float32Array(N * 3);
    for (let i = 0; i < N; i++) { /* seeded start, and per-particle radius / phase / speed in s.o */ } },
  step(s, dt, t) {
    const cx = 1.6 * Math.cos(t * 0.9), cy = 0.8 * Math.sin(t * 1.3);            // the attractor is a function of t
    for (let i = 0; i < N; i++) { /* spring each particle toward its own orbit about (cx, cy); integrate p += v * dt */ }
  },
});
// pose(t, k): const s = sim.at(t); write s.p into an InstancedMesh's matrices; mesh.instanceMatrix.needsUpdate = true;
```

**A portal: another world on a screen.** `k.view` renders a second scene and camera into a target every sample; a plane shows it. Use the same trick for a reflection or a picture in picture.

```js
const inner = new T.Scene(); inner.background = new T.Color("#1b2a4a");   // …add the inner world
const cam2 = new T.PerspectiveCamera(40, 16 / 9, 0.1, 50); cam2.position.set(0, 0.6, 4); cam2.lookAt(0, 0, 0);
k.target("inside", { w: 1280, h: 720, depth: true });
k.view("inside", { scene: inner, camera: cam2, target: "inside", pose: (t) => { knot.rotation.y = 1.2 * t; } });   // the inner world, posed from t
k.scene.add(new T.Mesh(new T.PlaneGeometry(3.6, 2.025), new T.MeshBasicMaterial({ map: k.targetTexture("inside"), toneMapped: false })));
```

**A custom post pass.** One shader on the accumulated frame: here a fringe that grows through the shot and film grain (a post pass is where a look's finishing lives).

```js
k.pass("fringe", {
  at: "post", uniforms: { uAmt: (t) => 0.002 + 0.004 * Math.min(1, t / D) },
  frag: `
    #include <r3/post>
    uniform float uAmt;
    void main() {
      vec4 s = r3Src(vUv);
      vec3 c = r3Grain(r3Chroma(uSrc, vUv, uAmt), gl_FragCoord.xy, uFrame, 0.04);
      gl_FragColor = vec4(c, s.a);
    }`,
});
```

And the habit that makes any of them land: block it in metres, look at stills and strips (§9), and ask what a shot like this would need that no preset gives. When the answer is a technique, write it.
