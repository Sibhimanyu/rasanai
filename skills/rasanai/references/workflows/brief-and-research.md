# Call 1: Brief, source modes, permissions and research

> Moved verbatim from the former single `SKILL.md`. References such as "§3d", "rule 18", "below" and "above" point into the sibling guides: the five-call contract and the hard rules are in [shared-contract](shared-contract.md); the phase guides are listed in `SKILL.md`.

## 1 · Brief

Push `brief` within the first minute, before any long work: a request with no source ("make me a video", "create a folder and start") gets `brief` pushed at once with `fields.subject` empty and the box asks for it; the answer arrives as `submit` with `value.source` (a URL, topic, script, PR link, or a path to a track or a footage folder). Read it, then fill in and re-push the brief (capture, route, brand) and wait again. A fresh console also shows that box on its own until the first push, and its answer arrives the same way. **Started from RasanAI Studio** (the request says BRIEF HANDOFF, and `session.json` already holds `steps.brief` with `status: working` and `fields.subject` filled): the user gave the brief in the app, so it is already submitted. Never push `needs_source` or an empty `subject`, never ask what the video is about and never wait for a source; research `fields.subject`, then push `brief` (awaiting) with `fields` filled, `captures` and `findings`, and wait for `submit`. Studio never shows that box. Studio's brief file (`rasanai-brief.json` in the project) may carry **`moments: [{id, role}]`** (up to 4; the request lists them under REFERENCE MOMENTS): the reference moments the user picked. Fetch each with `moments.mjs fetch <id> --run "$RUN" --role <role>` and pass them to the plan (step 3b below); they win over your own picks (`references/console.md`, The brief file). Otherwise read the request and the workspace, then push `brief` with what they already say: `fields` (`length_s`, `kind`, `subject`, `aspect`, `destination`, `narration`, and `brand_name` + `use_brand` when there's a brand), optional `choices` to narrow a field's menu, and `captures` (a few images of what you'll use). Work first, ask second:

```bash
node $SKILL_DIR/scripts/brand.mjs detect                         # DESIGN.md / design.md / BRAND.md / docs/DESIGN.md
node $SKILL_DIR/scripts/brand-assets.mjs import|add|check|apply|inventory|compile   # a user's brand kit: DESIGN.md + logos, fonts, media (references/brand.md "User brand kits")
node $SKILL_DIR/scripts/memory.mjs recommend --step aspect        # a remembered aspect to pre-fill
node $SKILL_DIR/scripts/lessons.mjs digest                      # ONE digest of what this user has taught and said (standing notes + a short "Recent verdicts" line); read it at step 0
```

- **1a · What are you making? (the format)**: the brief's first question, inside call 1. It asks WHAT the user is making (a launch film, a customer story, a reel from my clips), never how, so rule 1 holds. Run `node $SKILL_DIR/scripts/formats.mjs match --request "<the request, verbatim>" [--paths "<dropped files or folders>"]` and push the brief with its `format: {tile, option, why}` (nothing when it matches nothing: the page opens the 12 tiles); `console.mjs push` adds the `formats` list itself (`references/console.md`, The format picker). A request, a link or a dropped folder that already says it pre-selects the option as an editable chip; never ask it again. The submitted `format` (`{tile, option, scope?}`) is the decision: `node $SKILL_DIR/scripts/formats.mjs resolve --id <option> [--scope <s>]` gives the **route** (below), the **inputs** to ask for in its own words (a missing one is the subject box or an `ask`), the **source mode and case** (`research.mjs sources ... --kind "<kind>" --case <case>`, so the case is set, not guessed), the research, the story pass and the **story shapes** (ranked; Sure, Bold, Wild take the first three; `story.mjs pick` reports them as `format_shapes` from `decisions.json` `format`), the claim scope (a feature launch's "many uses or one job?" answer; none = the research decides) and the default length and aspect. Write `format` into `$RUN/decisions.json`. A `partial` format runs, and its caveat is said once in the route decision. **A `soon` format is said honestly** (its `say` line, in the console) with the nearest that works today offered as the choice; it is never quietly routed to `general-video` or anywhere else.
- **Route** (craft; push `route` done): the HyperFrames workflow that builds it, from HyperFrames' route table (`~/.claude/skills/hyperframes/SKILL.md` §2):

  | The video is… | Route |
  |---|---|
  | a product, app, company or site being launched / promoted / toured | `product-launch-video` |
  | a topic, article, notes or how-to told with invented visuals | `faceless-explainer` |
  | **an evidence film** (the Brief picked Evidence film: a technical explainer from the user's own data, scans or models) | `faceless-explainer` → [routes/evidence](routes/evidence.md) |
  | a GitHub pull request / code change | `pr-to-video` |
  | cut to a music track (lyric video, beat-synced promo) | `music-to-video` |
  | **a folder of raw clips** to cut together, with cards between clips and titles/captions on top | `reel` → **Footage reels** |
  | **a talking-head clip on a green or blue screen**, to be put into generated image worlds with motion graphics | `presenter` → **Presenter films** |
| one continuous talking-head clip + plain captions | `embedded-captions` |
  | talking-head / interview footage + designed overlay cards | `talking-head-recut` |
  | anything else: brand film, montage, custom multi-scene piece; a video for a talk or keynote | `general-video` |
  | one short unnarrated unit (a title, sting, stat hit, under ~10 s) | `motion-graphics` → **Single units** |
  | a short hand-painted cartoon with one recurring character | `character-cartoon` → [routes/cartoon](routes/cartoon.md) |

  Only when two routes are genuinely both right for different films, `ask`. Then set up the project and capture (work you can start while the user reads the brief):

  ```bash
  node $SKILL_DIR/scripts/video.mjs init --route <route> --project <kebab-name> --aspect <aspect>
  # product site:             node $SKILL_DIR/scripts/video.mjs capture --project-dir videos/<name> --url "<URL>"
  # topic / script / no site: node $SKILL_DIR/scripts/video.mjs capture --project-dir videos/<name> --no-capture --title "<title>" --text-file "$RUN/brief.txt"
  ```

  A failed or blocked capture is a **hard stop**: `ask` for screenshots or a brief; never build from a partial capture. `pr-to-video`: resolve the project folder with the workflow's `scripts/project-dir.mjs --pr <ref>` and run its fetch/ingest scripts. `music-to-video`: the user's track is the spine (ask for it with `ask` if missing). **Lyrics first**, before any story work, while the user reads the brief: the words and the music's structure are the raw material of the whole film (`references/lyric-video.md`, `references/lyrics.md`):

  ```bash
  node $SKILL_DIR/scripts/lyrics.mjs align --track <track> [--lyrics <lyric sheet.txt>] --out "$RUN/music/lyrics.json"   # lines[{text,start,end,words[{w,start,end,conf}]}]
  node $SKILL_DIR/scripts/lyrics.mjs audio --track <track> --out "$RUN/music/audio.json"                               # tempo, beats, downbeats, sections, kick/snare/hat onsets, envelopes
  ```

  A sheet the user pasted goes to `--lyrics`; without one the words come from the alignment itself. Read the words once yourself (anything mis-heard goes to the console as `ask` with the line and a recommended fix). Low-confidence words (`conf`) are listed in the activity feed; never ship a film that syncs to words nobody checked.

  **In the composition** (the runtime ships as `assets/three/rasan-music.js` with `stage3d.mjs install --project videos/<name>`, which `video.mjs inject` also does for 3D scenes, or for any film with `--runtime`): load both JSONs with `RasanMusic.load(LYRICS, AUDIO)` before the timeline is built, find a line with `RasanMusic.lyrics.get('some words of it')` and never by a time typed into the scene, and put each plate's cut on the beat before its first line (`RasanMusic.audio.lastBeatBefore(line.start)`, or the downbeat before it). `RasanMusic.gsapWords(tl, line, wordEls, {from, to, duration})` tweens each word on its sung start; the animators take `duration` from motion.md's scale (`references/lyrics.md`).
- **Research** (the crew; `references/crew.md`). Start it the moment the subject is known, right after pushing the brief, so it runs while the user reads:

  ```bash
  node $SKILL_DIR/scripts/research.mjs local-find --name "<product>" [--domain <site>]     # folder names only: is the product, or an earlier video of it, on this computer?
  # found something → console.mjs ask: may I read these folders (and run the app)? Only a yes goes to --local
  node $SKILL_DIR/scripts/crew.mjs plan --run "$RUN" --route <route> --subject "<name>" [--url <url>] [--public] [--local "<approved dirs>"] [--may-run] [--length <s>] [--project videos/<name>] [--brand "<brand>"] [--kind launch|promo|brand] [--pace fast]   # a named brand's launch/promo/brand film adds the brand-film phase and the style-match gates
  node $SKILL_DIR/scripts/crew.mjs brief --run "$RUN" --role <role> [--key <k>]               # per research member: writes its prompt, prints the Agent call
  ```

  **Budget.** `--budget lean|standard|full` (default standard) sets how much crew the film gets and prints the token estimate per phase and in total (also `crew/budget.json`, shown on the Brief call: `console.mjs push --step brief --merge --file <run>/crew/budget.json`). Lean = the film builder draws its own boards, 1 fix round, the film critic and one A/B (about 1M tokens on a direct film); standard = every desk, 2 fix rounds; full = every pass, up to 3. The level is an execution budget only: it never changes how many Story and Look alternatives the person sees (three, unless they chose another number or a series fixes it: `--alternatives N`), the story type, or the Story/Look distinction; a lean film makes the unchosen alternatives more compact. `--pace fast|standard|thorough` (the Studio app's setting) maps to lean|standard|full when no `--budget` is given, and `crew/policy.json` is the one production policy both read (lib/rules.mjs `productionPolicy`: creative choices, exploration depth, execution resources and render quality are separate axes; its numbers are proposed starting values, calibrated later). Say the level and its total when you push the brief; a user who asks for "show me looks" or deep exploration gets expanded exploration (`--deep`) and the extra spend is disclosed. `crew.mjs status` reports the estimated spend so far (`crew.mjs check ... --tokens N` records actuals). A long film does not fan out at once: the **spike** phase builds, drafts and gates ONE hero scene first (`--spike <n>`, default the peak beat), then dispatches the other animators with the spike as their worked example. Critics return `strengths[]`; `crew.mjs brief` puts them in the fix brief as `keep`, and the A/B juror flags a round that loses one (`strength_regressions`). A note with a point (and a finding with a `region` + `t`) becomes a marked crop: `crew.mjs marks --run <run> --file <draft.mp4>` -> `crew/marks/`; `crew.mjs strip ... --crop x,y,w,h` is the third zoom (sheet, strip, crop).

  **Know your model.** At setup, take MODEL and HARNESS from the setup output (or name your own model: you know it better than any env var) and pass `--model <id>` to `crew.mjs plan` and `crew.mjs brief`; the prompt each member gets is adapted to the model that will run it (`references/models.md`: the same goal and bar for every model, different wording and scaffolding; GPT runs also get a worked reel-quality example and a self-critique pass). On Claude Code, dispatch members with the `Agent(...)` line `brief` prints. Under Codex there is no Agent tool: run each member as the `codex exec ... &` line `brief` prints (members of a phase in parallel, `-s danger-full-access` so headless Chrome works), wait, and accept each with `crew.mjs check`; if `codex exec` is unavailable, plan with `--lean` and run the members in sequence yourself. Never ask the user anything in chat on Codex: the five calls are the console's.

  Dispatch every research member at once, in the background (`--public` for a product with a web presence and launch history: it adds the precedent researcher, who measures the brand's past launch films shot by shot). For a branded launch, promo or brand film (rule 19) the plan has no design researcher and no precedent researcher: the brand-film phase replaces both. Otherwise the **design researcher** (`design-research` phase) goes in the same batch: it needs only the subject and writes `research/design.md` and `research/design-refs.json` (the subject's visual world, its category's clichés, 8 to 12 library references), which the design-system designers read after the story is chosen. Accept each on `crew.mjs check`, then dispatch the **research lead**: it writes `$RUN/story/truth.md` (run `story.mjs truth` first for the template), the claims ledger, the brand's DESIGN.md verdict, the asset kit and `research/BRIEFING.md`. Read the briefing (one page), not the research. Its "Ask the user" items go to the console as `ask` (unreleased features, login-only screens), each with a recommended default. Push `research` done with one line ("Read 23 official pages, 9 real screens, ChatGPT's last 3 launch films; the brand is OpenAI Sans on white, accent only on actions"), and add the 3 to 5 most useful findings to the brief as `findings: [{text, source}]` (the page shows them under "What I found").
- **Brand (a step that always runs when a brand applies, rule 16)**: when the brief names a brand (`brand_name` / `use_brand`) or the product is a known brand, `research/brand/DESIGN.md` is required (`crew.mjs check` on the research lead fails without it or a workspace DESIGN.md): run the brand researcher, read the result with `brand.mjs read`, and **push `brand`** (`brand` = the `read` summary: roles, fonts, modes, warnings; `board` = `brand.mjs board`) and set `brand` in decisions before the story. A workspace DESIGN.md wins. Otherwise the research lead's verdict says whether `research/brand/DESIGN.md` (built from official sources) is the brand. **For a launch, promo or brand film of a named brand (rule 19) also run the brand film research** (`references/brand-film.md`): `brandfilm.mjs find --url <the brand's site>`/`fetch`/`frames`/`measure`/`card` into `$RUN/brand-film/` (the user's attached video first, at most 2 films, about 3 minutes on Fast pace; no film: the website and product screenshots, say so), then dispatch the **brand film analyst** (`crew.mjs brief --role brand-film-analyst`, accept with `crew.mjs check`), set `"film_style": "brand-film/FILM-STYLE.json"` in `$RUN/decisions.json` and push it with the `brand` step so the user sees it. Then `brand.mjs read --file <DESIGN.md>` for its roles, fonts and warnings; set `"brand": "<DESIGN.md>"` in `$RUN/decisions.json`. **The logo travels in the same push**: `brand.logo` = `{file: "research/brand/assets/<file>", kind, source_url}` for the file the film will place, or `{none: true, why}`; for `none`, post once `console.mjs activity --run "$RUN" --message "No official <Brand> logo file could be downloaded, so the end card uses the name in type. Add the logo file to fix it."`. At the storyboard step `crew.mjs storyboard` copies the files to `<project>/assets/brand/` and names them in DISPATCH.md and DIRECTION.md. `use_brand: false` in the submitted brief → films are drawn in each style's own colours.
- **1c · A reference clip (the user supplied a video as the bar: "like this", an intro, a launch film they love)**: analyse it, don't just describe it. `node $SKILL_DIR/scripts/research.mjs film --file <clip> --out "$RUN/research/films/reference"` (or `--url`) cuts it into shots and draws a contact sheet. **Look at the sheet**, then write `research/reference-moves.json`: 2 to 4 **move cards** (`references/moves.md` §2: carrier, frame A, the move with seconds, frame B and hand-off, the bridge, `says`, `generator`) for what the clip does, frame by frame, as a chain ledger would. Never technique names. `moves.mjs pack` puts these first among the inventors' exemplars, as the bar and never as content (an inventor may not reuse their objects or mechanism). Also write `research/reference-principles.json` (`{source, principles}`: 2 to 4 entries of `principle`, `why`, `effect`, `prerequisites`, `distinctive`, `check`; the schema is in `agents/critic.md`, Reference principles check): why it works, never what to copy. The Motion Director reads it and the film critic checks it on the render.
- **1d · Source mode (what the film is made from)**: before the research, name the source. A public product with a site is the default and needs nothing; anything else (the user's own footage, a brand folder with a guidelines PDF, an unreleased codebase, a document, a master video to cut down, a mix) goes through `node $SKILL_DIR/scripts/research.mjs sources --paths "<approved folders or files>" [--url <site>] [--code <dir>] [--kind "<what it is>"] [--public] --out "$RUN/sources.json"` (names and sizes only; only what the user approved). It gives the **spine** (the source the story is built from), the case, and `chips` for the brief ("47 clips (3 h 12 min) · Brand kit · slowpour.pt"); put them in `fields.sources`. Then `crew.mjs plan --sources "$RUN/sources.json"` picks the researchers by source, not by route. **A footage spine changes the film**: the script is written last, from what was shot. The Director runs the footage desk (`footage.mjs ingest|shots|transcribe|bites`; the language is detected, never defaulted, and a missing multilingual model is asked about, never downloaded), the loggers and the selects producer find the material, the writers are footage writers (three paper edits, not scripts), product-first (rule 15, G7/G9/G10/G11/G12) is off and the footage-first gate (GF) is on, and the brand comes from the user's own kit (the brand kit builder), not from a web search. A reel is Brief, Footage, Story, Look, Cut. One console `ask` carries what only the owner can give (names and titles, people on camera, quote tightening, anything unreleased or sensitive on screen); answers go to `footage/approvals.json`. The rules and files: `references/sources.md`.
- Answers: `submit <fields>` → write them into decisions.json; record `memory.mjs record --step aspect --value <WxH> --mode confirmed|auto`. Close `brief` with the sentence as the decision.

### New creative policy (a plan with `creative_policy_revision: 1`)

`crew.mjs plan` sets it for a NEW scene-production plan (`--creative-policy off` keeps the old behaviour; a saved plan keeps what it had). It changes backend content only: the five calls, their order and the console are unchanged. After the research desk run `node $SKILL_DIR/scripts/crew.mjs creative init --run "$RUN"` (the automatic reference selection from the local index, never a question to the user, and the provisional `creative/brief.json` skeleton), fill the skeleton from the truth sheet, claims and screens (`references/creative-quality.md`), then `crew.mjs creative check --run "$RUN"`. The brief is intent only: no timing (that is `motion/score.json`), no approval (that is the user's stage decisions). The story writers are not dispatched while it is still the skeleton.

### Revision 2 (`creative_policy_revision: 2`, v3)

`crew.mjs plan` gives a NEW scene-production plan revision 2 (`--creative-policy 1` keeps the legacy behaviour; a saved plan keeps its revision; an unknown revision stops with `unsupported_policy`). It resolves one effective policy and writes `creative/effective-policy.json` ([creative-policy.md](../creative-policy.md)): the existing pace, budget, model plan and approval order are unchanged, and a single-model choice wins over any role split. The user's native settings and the engine plan agree on one sentence per material field. Every pace may use the local indexed references and one bounded idea pass; web precedent searches count toward the source and time allowance, and an exhausted allowance is reported, never widened. What a run may spend on each phase is in [budget-context.md](../budget-context.md).
