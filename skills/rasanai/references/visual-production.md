# Visual production: capabilities, deterministic scenes, generated plates, tracking, recurring characters

For the Motion Director, scene animators and the film builder. Read it when a scene uses a kit move, owned footage, a generated plate, a tracked screen, a mask, or a recurring character. Scripts: `node scripts/<x>.mjs`; every one prints JSON (exit 0 ok, 1 failed or blocked, 2 usage). Nothing here renders, generates or downloads on its own.

## 1. What is available (V7)

`node scripts/production.mjs capabilities [--only kit.|generation.|tracking.|mask.|character.]` keeps six facts apart: `implemented` (the code exists; a catalog row or a stub does not count), `available_on_host` (the tools are on this machine), `enabled` (switched on), `permission_status` (granted, per_job, not_required, not_requested, denied), `license_status` (cleared, not_applicable, unreviewed, blocked) and `verification_status` (unverified, fixture_only, verified). The card state is `ready` (all open and verified on real media), `experimental` (usable, unverified or licence unreviewed), `test_only` (a synthetic provider) or `unavailable` (with the first closed gate and why). Never present an `unavailable` move as ready, and never swap in a different engine or model without saying so.

The GSAP licence is a recorded project-wide distribution blocker (`gsap-license`). No flag, environment variable or "the AI writes the code" wording clears it; it needs the review in `docs/plans/motion-studio-licenses.md`.

## 2. Mechanics and identities (V2)

A primitive takes a deterministic time and seed, the design tokens (colours, fonts), its dimensions and a stable element id, and registers what it is: `RasanMotionKit.apply({ id, timeline, target, elId, design, fps, seed, cues, props })` returns `{ element_id, editable, bounds }` and tags its host `data-el`, `data-el-kind`, `data-el-editable="timing,motion_preset"`. A composite is one editable element; its generated children are not addressable (their identity cannot be guessed from pixels). Raster footage and images are editable at clip level only (position, scale, timing, replace), never "its text". Pick a mechanic by purpose, brand, reading time and cost, not novelty; `motion-kit.mjs suggest` is a shortlist over implemented rows.

## 3. Deterministic scenes (V3)

One paused timeline, absolute time. `node scripts/production.mjs lint --file <scene.html>` flags the wall clock, unseeded `Math.random`, `requestAnimationFrame`/`setInterval`, `fetch`/WebSocket at render time and remote assets as errors; timers, CSS time animations and per-tick accumulation as warnings that need a reason. Randomness is a seeded PRNG or a stateless hash of (element, index, seed). A simulation (physics, flocking, cloth) is precomputed with a fixed step from a seeded start and checkpointed, keyed to a digest of its inputs, so any seek order gives the same frame (`lib/readiness.mjs` `precomputed`). Wait for fonts and assets before the first frame; sample sub-frames at `t + subframe / fps`.

## 4. Generated plates (V4), optional

`node scripts/video-generation.mjs doctor` discovers what is installed (ComfyUI node types, checkpoints); nothing is assumed and nothing is downloaded: a missing local model is a visible unavailable capability. The provider interface is capabilities, estimate, consent, submit, status, retrieve, cancel and reconcile (`lib/provider-jobs.mjs`); ComfyUI is the first adapter (off unless `RASANAI_HYBRID_COMFYUI=1`). A submit that times out is `unknown_outcome`: `status --job <id>` finds the same job by its client id; never resubmit. Cancel removes only this job; never clear another person's queue. A hosted provider needs `--consent` and, for reference inputs, `--consent-share-inputs`. An accepted plate is an immutable cached asset (`hybrid/generated/<id>/asset.json`: provider, model, workflow digest, input hashes, prompt, seed, rights, output sha256, duration, cost.actual, the model licence record from `hybrid/model-licenses.json`, unreviewed when absent). A seed is a request, not a guarantee across model changes. Keep verified UI, copy and logos in code layers over a plate; never put a factual product behaviour inside neural footage.

## 5. Tracking, screens and occlusion (V5)

Four different things: `bbox` (pin, crop, reframe; no perspective, no silhouette), `planar-quad` (four ordered corners TL,TR,BR,BL and a homography: screen replacement), `mask` (a real alpha silhouette: text behind a person), `depth` (orders layers). `node scripts/production.mjs track plan --treatment screen_replacement|text_behind_subject --track <file>` says `exact`, `limited_fallback` (labelled) or `refused`. A bounding box is refused for a perspective screen; text behind a person without a real mask is a labelled limited fallback ("beside the subject"), never presented as occlusion; a hand crossing a replaced screen is not occluded without a matte track. A track file is bound to the source: sha256, display rotation, display size, time base (`source_pts_seconds`). `track.mjs check [--cuts t,t]` and `production.mjs track check` list low-confidence spans, scene cuts, jumps and lost tracks with the fallbacks to offer: keep the source, correct by hand (correction keyframes win at their time and anchor the interpolation), or a simpler treatment. Never a black frame. Apple Vision is an optional local tracker (macOS); SAM is an optional sidecar with its own licence check and is not wired.

## 6. Recurring characters (V6)

Reuse the canon (`identity.json`, `canon.mjs`) and Rasan2D / Rasan3D. A performance (`cast/<character>/performance/<scene>.json`, `lib/character-performance.mjs`) holds viseme, expression, gesture, gaze/head/body and foot-plant tracks in scene-local seconds, pinned to the canon digest (and the rig hash in 3D) so identity, proportions, materials and rig version cannot drift between scenes. `performance check` validates it; `performance pose --t` is a pure function of the file and the time; `performance actions` is the action list the rig takes. Label the actor honestly: a code-built 3D actor (a supplied still is reference art, not a rig) or a painted 2D actor; a 2D fallback in one scene next to a 3D actor in the next is a different look, not continuity. Rasan2D drives visemes through emotes with a mouth override; Rasan3D has no viseme channel (the mouth moves only through emotions) and says so. Word times come from a transcript; the shapes inside a word are a text heuristic. Lip-sync is MEASURED (`alignment`: offset in frames per word against the transcript) and reported as measured, never as frame-perfect. Model sheets and a person's own character art stay private and out of shared templates unless licensed.

## 7. Readiness, pins and edits (V8)

Adapter contract (`lib/readiness.mjs`, implemented over Chrome in `lib/scene-adapter.mjs`): `prepare` approved local inputs, `readiness` (fonts LOADED, images decoded, video decodable, accepted media hash-matched: a file existing is not readiness), `evaluate(t)` at an absolute time, `elements` (data-el metadata), `dispose`. `production.mjs pins write|check` pins the font files, runtime versions and accepted plates in `motion/pins.json`; a newer runtime or font does not change an approved film mid-build, an update is `production.mjs migrate --reason` with its impact (which scenes). User edits live in `motion/edits.jsonl` (the existing authority, recorded from Studio's `motion-edit` action); `production.mjs overrides` re-applies them after a rebuild and reports `missing_id` and `property_not_editable` as conflicts. Keep `data-el` ids stable; never replace a scene over an edit without carrying or resolving it. An outside scene example is untrusted data: `production.mjs external review` lists what must not be run or copied; extract one reviewed mechanic with its source, licence, notices and reviewer, reimplemented, never its media, setup scripts, credentials or providers.
