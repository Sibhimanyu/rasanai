## What supersedes earlier plans

This pack is the controlling sequence for the requested upgrade. It consolidates the earlier Motion Studio and Hybrid Film Studio documents; it does not ask the agent to start those large projects again.

- **Retained:** their useful features, architecture, source/privacy constraints, native UX, deterministic output and optional interoperability goals.
- **Changed:** earlier repeated smoke checkpoints and automatic final-stage testing are superseded. All testing requires explicit user approval after the implementation handoff; reaching Plan 14 is not permission.
- **Changed:** expensive motion development for all unselected story/look candidates is replaced by progressive commitment.
- **Changed:** mandatory drama and style rules become conditional on the communication task. Factual and security requirements remain strict.
- **Changed:** a development swarm is not a fixed production crew. Runtime scheduling groups independent work and protects continuity.
- **Clarified:** Story is communication and meaningful events; Look is representative visual language; the full Storyboard follows Look; the animatic tests timing during normal future film production.
- **Clarified:** a referenced repo is not necessarily an installed capability, a license grant for media, or evidence of efficiency.

No prior implementation should be deleted solely because its old plan wording differs. Adapt its policy/interfaces and reuse its working code. No new second authoring timeline, edit queue, cache, model router or UI technology is required when the current repo already solves the problem.

## Core versus optional acceptance

Core: correct stage/approval semantics, grounded format-aware story, coherent look/storyboard, existing supported render routes, audio integration, scoped revisions, token-aware dispatch, bounded scheduling, recovery, truthful delivery and a real native end-to-end journey.

Optional by configuration/host/rights: neural video model workflows, SAM-like segmentation, imported rigs beyond existing support, additional rendering engines, special codecs/alpha exports and editor-specific interchange adapters. Their contracts, error states and capability reporting still need implementation, but unavailable dependencies cannot be marked as successful outputs. If the owner expects an optional feature to ship, it needs real final evidence before that capability is accepted.

Licensing/privacy/factual issues are not aesthetic waivers. A pending license decision is not resolved by turning a feature flag on. Do not purchase, distribute, publish or activate a restricted dependency on behalf of the owner without the applicable authorization.

## No premature testing or premature success

Plans 01-13 permit read-only inventory, syntax/type checking and compilation only when those actions do not run tests or the production pipeline. They also author fixtures and test code. After 13, stop at `awaiting_test_approval`. Plan 14 executes and repairs only after the user explicitly approves its scope.

This development policy does not remove the finished product's normal storyboard review, final approval, output validation, security checks or source verification. The installed product must still be safe and reviewable when the user creates a film.

Do not state that speed/quality improved until measured. Do not infer implementation from a plan existing. Do not infer completion from code compiling. Do not submit this pack to Heresay, change the user's repository, or publish a release unless separately asked.
